# Deploying GhostIQ

GhostIQ is one server (API + dashboard + SQLite on a volume) and one or more runners
(Playwright + Chromium) that connect out to it. Images are published to GitHub Container
Registry on every release tag:

| Image                                        | What                                    |
| -------------------------------------------- | --------------------------------------- |
| `ghcr.io/abhishek-dotcom15/ghostiq-server`   | API, dashboard, database at `/data`     |
| `ghcr.io/abhishek-dotcom15/ghostiq-runner`   | Runner agent (official Playwright base) |
| `ghcr.io/abhishek-dotcom15/ghostiq-mock-app` | The demo shop with planted bugs         |

Read [SECURITY.md](SECURITY.md) first: a reachable server must run with sign-in on.

## Any Docker host

```bash
docker volume create ghostiq-data
docker run -d --name ghostiq -p 3001:3001 -v ghostiq-data:/data \
  -e GHOSTIQ_ADMIN_TOKEN="$(openssl rand -base64 36)" \
  -e GHOSTIQ_PUBLIC_URL=https://ghostiq.example.com \
  -e GHOSTIQ_TRUST_PROXY=1 -e GHOSTIQ_HOSTED=true -e GHOSTIQ_RETENTION_DAYS=30 \
  -e GEMINI_API_KEY=... \
  ghcr.io/abhishek-dotcom15/ghostiq-server:latest
```

Put it behind TLS (Caddy, nginx, a platform load balancer). Then:

1. Open the dashboard, sign in with the admin token, create a project.
2. **Access & Keys** → create a key for the runner.
3. Start a runner anywhere that can reach both the server and the app under test:

   ```bash
   docker run -d --ipc=host \
     -e GHOSTIQ_SERVER_URL=https://ghostiq.example.com \
     -e GHOSTIQ_PROJECT_ID=<project id> -e GHOSTIQ_API_KEY=gq_... \
     ghcr.io/abhishek-dotcom15/ghostiq-runner:latest
   ```

## GitHub sign-in

Create an OAuth app (GitHub → Settings → Developer settings → OAuth Apps) with callback URL
`https://<your host>/auth/github/callback`, then set `GITHUB_CLIENT_ID`,
`GITHUB_CLIENT_SECRET` and `GHOSTIQ_GITHUB_ALLOWED_USERS` (comma-separated logins, or `*`).
The first GitHub user to sign in becomes admin.

## Render (blueprint)

[`render.yaml`](../render.yaml) defines the server (with a 2 GB disk), a runner worker and
the demo shop. New → Blueprint → this repository, then fill in the variables marked
`sync: false`. The runner's `GHOSTIQ_PROJECT_ID` and `GHOSTIQ_API_KEY` come from the
dashboard after the first sign-in; the admin token is generated by Render (copy it from the
service's environment).

### Read-only public demo

Sign in, create a project for the demo shop, run a few personas against the
`ghostiq-demo-shop` URL, then **Access & Keys → Make public**. Visitors can browse that
project's runs, findings and analytics without an account and cannot change anything.

## Updating and backups

- Pull the new image tag and restart; the schema is synced on start (`prisma db push`).
- Back up the `/data` volume (SQLite database, screenshots, traces), e.g. with
  `sqlite3 /data/ghostiq.db ".backup /backup/ghostiq.db"` plus a copy of the folders.
